# SALVO

Морской бой на твоей волне. Браузерная игра для перерыва между занятиями: сыграть с ботом, пригласить друга по ссылке и понять, как сыграть следующую партию лучше.

**[Играть в SALVO](https://salvo-play.vercel.app)** · **[Исходный код](https://github.com/nonbrainkid/salvo)**

Проект подготовлен по заданию второго этапа Narxoz Incubator 2026. SALVO — самостоятельный учебный прототип, а не официальный сервис университета.

## Что внутри

- Полноценная игра 10×10 с ручной и автоматической расстановкой, проверкой правил, попаданиями, потоплениями и результатом.
- Три сложности бота. Бот получает только историю своих выстрелов, без расположения твоего флота.
- Продолжение соло-партии после обновления страницы, история и статистика.
- Матч с другом по ссылке: сервер проверяет действия и скрывает чужой флот до окончания игры.
- Необязательный аккаунт с логином и паролем для истории и продолжения соло-партии на другом устройстве.
- Тренер после партии: анализ точности, поиска и лишних выстрелов. Это объяснимый алгоритм, а не запрос к языковой модели.
- SALVO Pro в явно обозначенном деморежиме: темы оформления и более подробный разбор. Платежи не принимаются.

Главная особенность — короткий цикл «сыграл → понял ошибку → попробовал иначе». Регистрация не мешает первой партии. Приглашение друга создаёт понятную причину поделиться игрой.

## Правила

У каждого игрока 10 кораблей: один на 4 клетки, два на 3, три на 2 и четыре на 1. Всего 20 палуб. Корабли прямые, лежат горизонтально или вертикально, не пересекаются и не касаются даже углами.

Игрок выбирает клетку поля противника. Промах передаёт ход; попадание и потопление сохраняют ход. Повторно стрелять нельзя. Побеждает тот, кто первым уничтожит все 20 палуб. Клетки вокруг потопленного корабля можно исключить из поиска, поскольку корабли не соприкасаются.

В ручной расстановке выбери корабль и направление, затем клетку начала. На телефоне используются те же нажатия — перетаскивание не требуется.

## Локальный запуск

Требуется Node.js 24 и npm. На Windows, если PowerShell блокирует `npm.ps1`, используй `npm.cmd`.

```bash
npm ci
npm run dev
```

Vite покажет адрес приложения. Соло доступно без базы. Для аккаунтов и матчей с другом запусти API во втором терминале. Есть два варианта.

**Neon Postgres:** скопируй `.env.example` в `.env.local`, установи `DATABASE_URL` и выполни:

```bash
npm run db:setup
npm run dev:api
```

**Временная память для локальной разработки:** установи `SALVO_LOCAL_MEMORY=1` в `.env.local`, оставь `DATABASE_URL` пустым и запусти `npm run dev:api`. Аккаунты и комнаты этого режима пропадут при перезапуске API. В Vercel/production этот режим запрещён.

Клиент проксирует `/api` на порт 3001. Секреты никогда не должны иметь префикс `VITE_` или попадать в Git. Файл `.env.local` исключён из репозитория.

## Проверки

```bash
npm test
npm run build
npm audit --omit=dev
```

Для полной проверки запущенного API с настоящей базой: `npm run verify:api`. По умолчанию проверяется `http://localhost:3001`; другой адрес задаётся переменной `SALVO_TEST_URL`. Скрипт создаёт отдельную тестовую комнату и аккаунт, проводит матч, проверяет скрытие флота, двойной выстрел и вход со второй сессии. Он не использует существующие пользовательские аккаунты.

Тесты покрывают правила, генерацию флотов, работу бота и серверные сценарии. CI выполняет тесты и сборку при изменениях в `main` и pull request. Сценарии ручной демонстрации приведены в [DEMO.md](DEMO.md).

## Устройство проекта

| Область | Файлы | Ответственность |
| --- | --- | --- |
| Правила и бот | `src/game/engine.ts` | Чистые функции без React, DOM и базы данных |
| Общие типы | `src/shared/contracts.ts` | Состояние партии, выстрелы, история, ответы API |
| Интерфейс | `src/App.tsx`, `src/components`, `src/styles.css` | Расстановка, игра, аккаунт, статистика и Pro |
| API-клиент | `src/lib/client.ts` | Запросы с таймаутами и понятными ошибками |
| Сервер | `server`, `api` | Авторизация, проверка онлайн-ходов, хранение |
| Деплой | `vercel.json` | Статический клиент и Vercel Functions |

Соло работает на клиенте. Компьютерный соперник получает только наблюдаемые результаты выстрелов: простой выбирает случайные клетки, более сильные продолжают поиск вокруг попадания и используют вероятные позиции ещё не потопленных кораблей.

Онлайн-матчи хранятся на сервере. Клиент отправляет действие, сервер проверяет участника, фазу игры, очередь и клетку. Запись с проверкой версии предотвращает два одновременных конфликтующих хода. Ответ содержит свой флот и видимые результаты выстрелов. Флот противника раскрывается только по завершении.

Пароли хешируются scrypt; сессии используют HttpOnly cookie, а база хранит хеш токена. Запросы изменения состояния проверяют источник. Ограничения частоты и размера запросов снижают риск злоупотребления. Вход без email выбран, чтобы не требовать почтового сервиса для прототипа.

## Технологии и заимствования

- React, TypeScript, Vite — интерфейс и сборка.
- Node.js, Vercel Functions, Neon Postgres, `@neondatabase/serverless` — сервер и база.
- Vitest — тестирование.
- Lucide — иконки, ISC License.
- Golos Text и Unbounded через Google Fonts — шрифты, SIL Open Font License; предусмотрены системные fallback-шрифты.
- Готовый шаблон игры не использовался. Игровая логика, алгоритмы соперника, компоновка интерфейса и серверные сценарии написаны для SALVO.
- AI-инструмент: OpenAI Codex. Работа разделена между агентами движка, интерфейса и backend, затем интегрирована и проверена основным агентом. AI применялся к планированию, коду, тестам и документации. Авторы проекта должны понимать и уметь объяснить решение; сценарий защиты находится в `DEMO.md`.

## Монетизация как гипотеза

Базовая игра и матчи с другом остаются бесплатными. Возможный платный продукт — оформление и подробный анализ личной игры; затем отдельные инструменты организатора дружеских турниров. В текущем прототипе Pro активирует функции бесплатно с явной пометкой «демо». Нет списаний, рекуррентной подписки или обещания уже существующей выручки. Готовность платить предстоит проверить на интервью и реальном использовании.

## Ограничения

- Нет платежей, рейтинговых матчей, турниров, списка друзей и публичной таблицы лидеров.
- Тренер основан на правилах и наблюдаемых выстрелах; он не гарантирует победу.
- Соло-статистика поступает с клиента и не используется как доверенный рейтинг. Игрок с DevTools может посмотреть локальный флот бота. Это не относится к скрытому флоту в онлайн-матче.
- Синхронизация комнаты использует периодические HTTP-запросы, а не WebSocket; между устройствами возможна небольшая задержка.
- Доступ к комнате связан с cookie данного браузера. После удаления cookie доступ к этой комнате восстановить нельзя; вход в аккаунт на другом устройстве переносит соло-прогресс и историю, но не роль в открытой комнате. Приглашение действует семь дней.
- Нет восстановления пароля по email. Для демонстрации можно создать отдельный аккаунт, не вводя персональные данные.
- Сохранение в браузере зависит от доступности LocalStorage. Для межустройственного продолжения нужен вход и подключение к API.
- Бесплатные тарифы Neon и Vercel имеют ограничения; это прототип для проверки и небольших дружеских матчей, не сервис с SLA.

## Публикация на Vercel

Импортируй репозиторий, выбери Vite, подключи Neon и добавь серверный `DATABASE_URL`. Выполни миграцию для той же базы. Клиент собирается командой `npm run build`, каталог результата — `dist`; функции расположены в `api`.

Перед сдачей проверь публичную ссылку без входа в Vercel: сыграй до результата, обнови страницу во время игры и открой комнату в двух разных браузерах. Репозиторий должен соответствовать опубликованной версии. Не отправляй `.env.local` или токены проверяющим.
